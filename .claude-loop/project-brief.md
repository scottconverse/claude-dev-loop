# Project brief

> Loaded at the start of every session. Keep it short, current, and true.

## What we're building
_One paragraph: the product/system, who it's for, and the core feature that defines "it works."_

## Why it matters
_The problem this solves and the cost of getting it wrong._

## Current state
_Where things stand right now — honestly. What works (verified), what doesn't, what's untested._

## Definition of success
_The binary, observable condition that means this is done. Prefer "a new user can do X end to end"
over "the code is written."_

## Constraints & non-negotiables
- _Platforms / stack / versions that are fixed._
- _Things that must never happen (data loss, sending without approval, etc.)._
- _Dependencies the core feature needs (services, models, binaries, credentials) — and whether they're present._
