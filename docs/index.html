For Claude Code in the Cowork Desktop app

A durable dev-loop for Claude Code that refuses to fake “done.”

A development-workflow operating system that gives Claude a persistent vault, verifiable goals and self-checking loops, honest run logs, hard approval gates, and an honesty contract that makes “verified” mean proven in the same turn — or else say “not verified.”

Install it Read the contract

Requirements: Python 3 (standard library only — no pip installs) and PowerShell. That’s it.

The problem

Assistants overclaim — then quietly work around what’s missing.

The failure mode this system exists to kill: an assistant that claims work is done, claims something is verified, or silently routes around a missing dependency — a model, a binary, a service, credentials — and calls the result finished. “I tested around it” is not a third option.

“Verified — all done. ✅”

No evidence. No command, no output, no observation in the same turn. A claim of proof without the proof.

“Tests pass, so the feature works.”

Conflated. “Unit tests pass” is not “the user-facing feature works end to end.”

“The model wasn’t there, so I mocked it — works.”

Worked around. An absent dependency was bypassed and the path was never actually exercised.

“Not verified — here’s what’s blocking it.”

Honest. A hedge with a plan beats a confident guess. Always a better outcome than a false “finished.”

What’s in the box

Seven parts, one contract.

Everything lives in a plain-Markdown vault a human can read and edit, maintained through standard-library Python helpers so the formats stay machine-parseable.

Vault memory

A persistent .claude-loop/ directory — project brief, preferences, approval gates, open loops, automation registry, decision log — loaded at the start of every session.

Goals with verification criteria

Each goal card carries a binary done-list. A criterion flips to [x] only after its verification step actually ran and passed.

Self-checking loops

A recurring task with a contract: trigger, action, verifier, budget, and stop condition. A loop with no verifier isn’t a loop — it’s a wish.

Run logs

Every loop iteration is appended as a run — observed, action, the real verifier result including failures, next step. An all-PASS log is a red flag, not a success story.

Approval gates

Free locally; ask first for anything outward or irreversible — push, deploy, send, delete, install, spend, third-party. Gated actions get queued, never assumed.

The honesty contract

The reason the system exists: no “verified / done / ✅” without evidence in the same turn. Read first, every session — these rules override convenience.

The status dashboard

A generated, self-contained dark-themed status.html — every goal’s progress, every loop’s run count and last verifier, pending approvals, and open loops. No external dependencies.

Install — Windows PowerShell

One line, from inside the repo.

Copies the skill/ payload (SKILL.md + CLAUDE.md), scripts/, and vault-templates/ into %USERPROFILE%\.claude\skills\claude-dev-loop.

PowerShell 
powershell -ExecutionPolicy Bypass -File installers\install.ps1

SKILL.md (YAML frontmatter) is the loader Claude Code discovers; CLAUDE.md beside it holds the full operating contract. Restart the Cowork Desktop app afterward so it picks up the new skill. On this machine the Python launcher is py.

How it works

From install to a finalized, dashboard-clean session.

All scripts are standard-library Python 3 and take --target <project-root> as their first argument.

1

Install the skill

Run installers\install.ps1, then restart Cowork Desktop. The skill activates at the start of any session in a project that has — or should have — a .claude-loop/ vault.

2

Bootstrap a vault

bootstrap_vault.py --target . creates .claude-loop/ with its Markdown files and goals/, loops/, runs/ subdirs. Re-runnable — it skips files that already exist. Then fill in the project brief, preferences, and approval gates.

3

Declare goals & loops

create_goal.py writes a goal card with --objective, --criteria, and --verify steps. create_loop.py writes a loop spec with --trigger, --action, --verifier, --budget, and --stop — and registers it in the automation registry.

4

Record runs & queue approvals

After every loop iteration, record_run.py appends what you --observed, the --action, the real --result, and the --next step. Hit something gated? queue_approval.py logs it with --action, --reason, --risk, and --risk-level — then you keep doing non-gated work until the user answers in chat.

5

Finalize & refresh the dashboard

Before closing, finalize_check.py fails on pending approvals, active goals with zero proven criteria, or unresolved open loops. memory_check.py reports health any time. Then loop_status.py --html regenerates status.html so the next session starts from truth.

The honesty contract

CLAUDE.md · §0 · read this first, every session

No “verified” / “done” / “✅” without evidence in the same turn. A claim of success must be accompanied by the command that proves it and its actual output, or an on-screen observation you just made. If you don’t have the evidence in front of you, the correct words are “not verified” or “I have not run this.”
  • A goal criterion is checked off only after its verification step actually ran and passed.
  • Never work around an absent dependency and call the feature tested — install it and run the path, or say plainly it was not exercised.
  • Distinguish code-verified from runtime-verified. Surface lost or reverted work immediately and loudly.
  • When unsure, say so. A hedge with a plan beats a confident guess.
